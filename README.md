# ADD Home Healthcare — one-page website

Static site (plain HTML/CSS, no framework) built and deployed to GitHub Pages with `make`.

```
config.mk        ← domain and deploy settings (edit this)
Makefile         ← build / serve / check / deploy
site/            ← source files (contain __SITE_URL__ / __BASE_PATH__ placeholders)
  index.html       the one-page site
  404.html         not-found page
  robots.txt, sitemap.xml
  assets/          logo.png, logomark.svg, favicon.svg, apple-touch-icon.png
dist/            ← generated by `make build` (git-ignored, never edit by hand)
```

## Quick start

```bash
make            # list tasks and show the current target URL
make serve      # build and preview at http://localhost:8080
make deploy     # build and publish to the gh-pages branch (or just push to main, see below)
```

Requires `make`, `sed`, `git` and (for `serve`) `python3`. Works on macOS, Linux and WSL.

## Changing the domain

All URLs (canonical, Open Graph, Twitter, JSON-LD, robots.txt, sitemap.xml, CNAME) are derived from `config.mk`, so the domain is changed in one place:

```make
DOMAIN    ?= www.addhomehealthcare.com   # hostname only
BASE_PATH ?= /                           # "/" for a custom domain or user site
USE_CNAME ?= 1                           # writes dist/CNAME so GitHub keeps the domain
```

Then `make deploy`. You can also override per run without touching the file:

```bash
# Custom domain
make deploy DOMAIN=addhomehealthcare.org

# Plain GitHub Pages project site: https://<user>.github.io/<repo>/
make deploy DOMAIN=<user>.github.io BASE_PATH=/<repo>/ USE_CNAME=0
```

`make config` prints the resolved values; `make check` fails the build if any placeholder is left unreplaced or a referenced asset is missing.

## Deploying with GitHub Actions (recommended)

`.github/workflows/deploy.yml` runs `make build` and publishes `dist/` to GitHub Pages on every push to `main` (or manually from the **Actions** tab).

1. Create the repository and push this source to the `main` branch.
2. In GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main`. The workflow builds and deploys the site; the URL appears on the run summary.
4. For a custom domain, add it under **Settings → Pages → Custom domain** and point your DNS at GitHub Pages (`CNAME` record for `www`, or the four `A` records for an apex domain). Turn on **Enforce HTTPS**.

The workflow builds with the values in `config.mk`; change the domain there (for a plain project site: `DOMAIN=<user>.github.io`, `BASE_PATH=/<repo>/`, `USE_CNAME=0`). After deploying, it smoke-tests the live URL and warns if the `og:image` social card is missing. Edits to only `README.md` or `.gitignore` don't trigger a deploy.

## Manual deploy (gh-pages branch)

Alternatively, without Actions:

1. Run `make deploy`. It builds `dist/` and force-pushes it to the `gh-pages` branch of `origin` (override with `REPO_URL=...`).
2. In GitHub: **Settings → Pages → Source: Deploy from a branch**, branch `gh-pages`, folder `/ (root)`.
3. Keep `USE_CNAME=1` for a custom domain so each deploy re-creates the `CNAME` file.

Every later update is just `make deploy`.

## Before going live

`make build` prints a note for anything still marked `TODO` in `site/index.html`:

- **Social preview image**: add `site/assets/og-image.jpg` (1200×630). The `og:image` / `twitter:image` tags already point at it.
- **Contact form**: set the form `action` to your form backend (Formspree, Basin, Getform…). GitHub Pages has no server. The page shows the success message after a successful submission; a honeypot field (`_gotcha`) is included.
- **Business hours**: currently Monday–Friday 9:00 AM–5:00 PM (from the content draft); confirm, in the page and in the JSON-LD block.
- **Privacy Policy / Terms of Use** links point to `#privacy` / `#terms`; add real pages.
- **Photos** are hotlinked from Unsplash (free licence). For production, download the ones you keep into `site/assets/` and update the `src` paths so the site doesn't depend on a third-party CDN.
- Confirm service definitions (IHSS, LST), eligibility and licensing claims per the content document's pre-publication checklist.
